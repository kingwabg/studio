  글자 규칙 검사는 이 스캐너의 재사용이다.

## 결정 (2026-07-31 준하)

| 항목 | 결정 | 이유 |
|------|------|------|

## 무엇을 만드나

맞춤법과 서식 규정이 **같은 파이프라인**을 탄다. 사용자 눈에는 밑줄 색 차이뿐이고,
만드는 쪽은 규칙 목록만 늘린다.

| 단 | 하는 일 | 새 파일 |
|----|---------|---------|
| 1. 규칙 | 맞춤법 규칙 + 서식 규격을 한 형식(`LintRule`)으로 | `src/lint/rules.ts` |
| 2. 검사 | 문단을 훑어 `{para, from, to, msg, fix}` 목록 산출 | `src/lint/scan.ts` |
| 3. 표시 | 위반 구간 → `getSelectionRects` → 캔버스 위 밑줄 | `src/lint/overlay.ts` |
| 4. 적용 | 고침 하나를 명령으로 실행(undo 1회) + 카드 UI | `src/lint/apply.ts`, `src/ui/lint-card.ts` |

**하지 말 것**
- 기존 `spell-dialog.ts`를 지우지 않는다 — 1차에서는 규칙 목록만 `lint/rules.ts`로 옮겨
  양쪽이 같은 소스를 쓰게 한다. 대화상자 제거는 인라인이 자리를 잡은 뒤.
- 문서 전체를 매번 훑지 않는다. 보이는 쪽 + 디바운스가 성능 계약이다.
- 오탐이 나는 규칙은 넣지 않는다. "가끔 맞는 규칙"은 검사기 신뢰를 통째로 깎는다.

### 서식 규격 기본 1벌 (1차 범위)

```
본문 글꼴 = 함초롬바탕            → 고침: 글자 속성 적용
본문 크기 = 10pt                  → 고침: 크기 적용
본문 굵기 = 보통(제목 문단 제외)   → 고침: 굵기 해제
표 머리글 행 = 굵게 + 회색 배경    → 고침: 셀 속성 적용
표 안 글자 = 9pt 이하             → 고침: 크기 적용
```

## 판정식 ★

1. 규칙 위반이 있는 문서를 열면 **1초 안에** 밑줄이 뜬다
2. 밑줄 클릭 → 카드 → **[적용]** → 문서가 실제로 바뀌고 그 밑줄이 사라진다
3. **Ctrl+Z 한 번**으로 그 적용이 되돌아간다 (되돌리기가 안 되면 아무도 [전부 적용]을 안 누른다)
4. **[전부 적용]** 후 재검사하면 위반 0건
5. **오탐 0건** — 규격에 맞는 문서에는 밑줄이 하나도 안 뜬다
6. 타이핑 중 프레임 저하 없음 — 100문단 문서에서 디바운스 후 검사 **50ms 이내**

## 단계

- **1차** 뼈대: 맞춤법을 캔버스로 꺼내기(밑줄 + 카드 + 적용 + undo). 규칙은 기존 것 재사용.
  → 뼈대가 검증되면 서식 규칙은 목록에 줄을 더하는 일이 된다.
- **2차** 서식 규칙 5종 + 우측 패널 목록 + [전부 적용]
- **3차** 센터별 규격 편집(sc- 관리자 화면) — 이번 범위 밖

## 검증 사다리

수정마다: `npx tsc --noEmit` → `node scripts/check-file-size.mjs` →
`npx tsx --test tests/*.test.ts` → e2e 신규 `lint-inline.test.mjs`(판정식 1~4를 헤드리스로).
판정식 6은 e2e 안에서 `performance.now()` 측정으로 박는다.

## 위험 핀 · 중단 규칙

- 깨지면 멈출 것: `e2e/format-sweep.test.mjs`(글자·문단 속성 왕복), `e2e/edit-pipeline.test.mjs`,
  `e2e/copy-paste.test.mjs` — 오버레이가 좌표계나 입력 경로를 건드렸다는 신호다.
- 되돌림 조건: 판정식 5(오탐 0건)를 못 맞추면 그 규칙을 **뺀다**. 규칙을 느슨하게
  고쳐 통과시키지 않는다.
- 오버레이는 렌더 파이프라인 안이 아니라 **별도 레이어**로 그린다. 페이지 렌더에 손대면
  조판 회귀가 난다(이 저장소의 반복 함정).

## 실행 결과

### 1차 (2026-07-31) — 뼈대
판정식 6/6 통과, e2e `lint-inline.test.mjs` 실측:
① 1초 안에 밑줄 2건 ② 카드 [적용] → 문서 변경·밑줄 감소 ③ 되돌리기 한 번으로 복구
④ 전부 적용 후 0건 ⑤ 정상 문장 오탐 0건 ⑥ 100문단 검사 0.3ms

**설계 변경**: 규칙을 `lint/rules.ts` 로 옮기지 않았다 — `ui/spell-dialog.ts` 의
`scanDocument`/`SPELL_RULES` 를 그대로 import 하면 이미 단일 소스다. 옮기는 것은 순수 이동
비용이라 하지 않았다.

### 2차 (2026-07-31) — 서식 규정 5종 + 패널
판정식 통과, e2e `lint-format.test.mjs` 실측:
① 규격 위반(함초롬돋움 14pt) → 밑줄 2건 ② [전부 적용] → 함초롬바탕 10pt 복귀
③ 되돌리기 **한 번**으로 14pt·함초롬돋움 동시 복구 ④ 표 머리글 굵게 지적 → 적용 후 굵게
⑤ 규격대로인 문장 서식 지적 0건 ⑥ 패널 "검사 N건 · 맞춤법 N · 서식 N"
합산 검사 시간 100문단 **14.1ms**(상한 50ms).

**엔진 추가**: `getTables(sectionIdx)` — 형제 API 는 표 위치를 이미 알 때 쓰는 것들이라
문서 전체를 훑는 쪽이 문단×컨트롤을 예외로 찔러 판별해야 했다. 잠금 = `tests/officex_get_tables.rs` 3건.

**설계 변경 3건(모두 실측 근거)**
1. `dropOverlaps` 를 맞춤법에만 적용 — 서식 지적은 같은 구간이 "글꼴도 크기도 다르다"인 게
   정상인데 겹침으로 걸러 **크기 위반이 통째로 사라졌다**(실측 결함).
2. `[전부 적용]` 을 스냅샷 1개로 묶음 — 건별로 기록하면 20건 고친 뒤 되돌리려면 20번
   눌러야 한다. 판정식 ③의 취지("되돌리기가 안 되면 아무도 안 누른다")를 일괄에도 적용.
3. `tableMaxPt` 기본값 9 → **10** — 엔진 기본 표 글자가 10pt라 9로 두면 새로 만든 표가
   전부 지적된다. 늘 켜진 경고는 아무도 안 본다. 센터 규격이 9pt면 3차에서 낮춘다.

**남은 한계(명시)**
- 표는 **셀 첫 문단의 첫 글자만** 본다(셀 전체 구간 분해는 표 하나에 수백 회 조회).
  셀 중간부터 다른 서식이면 놓친다.
- 빈 셀은 건너뛴다 — 밑줄 그을 글자가 없다.
- `[무시]` 는 이번 세션 한정(문서에 저장하지 않는다).
- 3차(센터별 규격 편집)는 착수 전.
